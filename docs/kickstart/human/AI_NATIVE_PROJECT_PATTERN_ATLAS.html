AI-native Project Kickstart · Human-facing Pattern Atlas

十個可跨 project 重用嘅 operating patterns

呢套 patterns 由實際 AI-assisted software delivery 中抽象出嚟：重點唔係某個 framework，而係點樣令 product intent、architecture、agent work、evidence、Git 同 release 形成一套可控、可驗證、可持續演化嘅 operating model。

總原則： Experience 決定方向；Specs 保護契約；Repository state 勝過 stale plan；PR 應交付 coherent vertical slice；agent complexity 只按風險證據升級；所有 claim 都要有可推翻舊缺陷嘅 evidence；integration、review 同 release 必須分開。

適合用喺

  1. AI-heavy greenfield project
  2. Codex / agent worktree workflow
  3. 複雜 UI / simulation / domain system
  4. 多人 + 多 agent 平行開發

01

Baseline Specs + Current Repo Truth + Risk-Adaptive Delivery

PRD / SDD / ADR 保留長壽命 intent 與 contracts；真正 execution 每輪由 current repository + current gap 重新生成，避免 stale task inventory 變成錯誤權威。

Layered Flow

Use when

Project 有長期 specs，但 implementation 會快速演化，尤其 agent 可能持有舊計劃。

Avoid

將巨大 task inventory 當永久 execution queue；歷史 prompt 不應覆蓋 current repo truth。

02

Coherent Vertical Slice PR

每個 PR 應盡量交付一個 Visible → Operable → Coherent → Verifiable outcome，而唔係先完成一整層再等幾個 PR 後先見到 user value。

Vertical Slice

Rule of thumb

Reviewer 應該可以用 user-observable outcome 描述個 PR，而唔只係「完成咗某 layer」。

Benefit

減少 integration surprise，令每次 merge 都保持 coherent system state。

03

Canonical Domain State → Derived Views

核心 domain truth 只保留一份；UI、renderer、readout、task、report、projection 等全部 derive，而唔各自偷偷重算。

Hub & Spoke

Use when

同一 domain truth 有多種 representation：simulation、dashboard、editor、financial model、workflow app。

Failure smell

不同 view 各自 copy calibration / unit / sign / business rule，最後 drift。

04

Evidence Integrity

Test pass 唔等於 claim 被證明。真正 evidence 必須令舊 defect 會 fail，而且唔可以由 reload、mock、injected value、proxy attribute 等 bypass 真實行為。

Evidence Funnel

Key question

「如果舊 bug 仲喺度，呢個 test 會唔會紅？」如果未必，就只係 activity，唔係證據。

Scope

適用於 tests、manual validation、screenshots、metrics、review claims、completion reports。

05

Repository-Centric Durable Context

Repository 係 durable memory；handoff 只傳 current delta。避免每輪 prompt 複製整段歷史，令 context 愈滾愈大。

Context Pyramid

Why it matters

減少 token bloat、stale context、copy-paste contradiction，亦方便 reviewer 由 repo 重新驗證。

Boundary

`CURRENT.md` 係 reviewer navigation / implementation claim，唔係 authoritative source of truth。

06

Separate Implementation Authority from Merge Authority

做 implementation 嘅 agent 可以提供 evidence claim，但當要作 merge verdict 時，應由獨立 reviewer 重新看 actual diff、tests、PR head。

Swimlane Gate

Use when

PR 已經去到真實 merge decision，或者 regression risk 夠高，需要 challenge implementation claim。

Do not overuse

Micro edit 同一般 focused local fix 唔應該強制跑獨立 reviewer。

07

Fail-Closed VCS Operations

Agent 做 Git publication 時唔靠 upstream / push.default 猜 destination；所有 branch、base、remote ref 都要 explicit，而且任何異常都 stop 而唔自動 repair。

Safety Sequence

Principle

Safety-sensitive VCS actions 應該 fail closed，而唔係估個最可能意圖再自動修。

Especially useful

多 worktree、多 agent、parallel PR、production branch、automated PR publication。

08

Integration ≠ Review ≠ Release

`main` 可以持續吸收 integration，但 production 應由已 review、已選定嘅 release point 明確 promotion，而唔係「main 一郁 production 就跟住郁」。

Multi-Gate Model

Benefit

平行 PR 可以繼續 merge，又唔會逼 production 一定等全部大 PR 收尾先可 deploy。

Key separation

Integration gate、merge/review gate、release/promotion gate 係三個唔同 decision。

09

Freeze Accepted Areas

一旦一個視覺、interaction、contract、API 或 architectural area 已被接受，就成為 constraint；下一輪只 expand 未完成範圍，除非需求明確 reopen。

State Loop

Design use

避免 agent 每輪順手重新設計已確認 UI、hero、layout、interaction。

Engineering use

對應 no proactive refactor / generalization / unrelated diagnostics；bug fix 唔應該偷偷擴大 scope。

10

Route by Cognitive Dependency, Not File Ownership

「touches a domain」唔等於「需要該 domain specialist」。只有當 task 真正依賴嗰個 domain 嘅 reasoning、invariant 或 shared contract 時先升級 specialist。

Decision Tree

Example

改 renderer-adjacent component 入面一個 label ≠ renderer specialist；改 render-target ownership = renderer specialist。

Result

減少 orchestration ceremony、context cost 同 specialist overuse，同時保留真正 contract-change 時嘅深度。
